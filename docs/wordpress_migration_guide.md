# WordPress 移行ガイド

本ドキュメントは、既存の WordPress サイトから sorus への移行作業手順を解説する公式ガイドです。
IT専門知識のない方でも迷わず移行できるよう、具体的な操作手順を説明します。

---

## 1. 移行の全体像

sorus の WordPress インポーターは、純 Go によるシングルバイナリで動作し、以下の処理を自動かつ安全に実行します。

1. **記事・固定ページの取り込み**: WordPress の WXR XML 形式をパースし、タイトル、本文、公開日時、スラッグ、ステータスを取り込みます。固定ページは記事とは別の種類（ページ）として取り込みます。
2. **HTML から Markdown への自動正規化**: WordPress 特有のショートコードを無害化・クリーンアップし、見出し・リスト・テーブル・引用をクリーンな Markdown に変換します。
3. **画像の自動ローカライズと WebP 化**: 記事内の画像を自動ダウンロードし、EXIF メタデータを完全除去した上で、4段階のレスポンシブ WebP 形式に一括変換してローカル（`/uploads/`）に保存します。
4. **旧 URL からの 301 リダイレクト自動登録**: WordPress 時代の URL（パーマリンク）から sorus の新 URL への 301 恒久転送を自動登録し、SEO 評価と被リンクを保護します。
5. **全文検索インデックスの自動構築**: 取り込んだ公開記事を Bleve 検索インデックスへ自動同期します。
6. **防弾トランザクション**: 途中でエラーが発生した場合は、生成された画像を含めてすべて自動ロールバックされ、中途半端なデータが残りません。

---

## 2. ステップ 1: WordPress からデータをエクスポートする

まずは WordPress 管理画面から、移行対象のデータを XML ファイルとして書き出します。

1. WordPress の管理画面（`/wp-admin`）に管理者権限でログインします。
2. 左メニューの **「ツール」 > 「エクスポート」** を開きます。
3. エクスポートする内容を選択します：
   - 通常は **「すべてのコンテンツ」** を選択します。
   - 記事のみを移行したい場合は **「投稿」** を選択します。
4. **「エクスポート用ダウンロードファイルをダウンロード」** ボタンをクリックします。
5. パソコンに `.xml` ファイル（例: `my-site.wordpress.2026-10-21.xml`）が保存されます。

---

## 3. ステップ 2: sorus でインポートを実行する

エクスポートした XML ファイルを sorus に取り込みます。管理画面から取り込む方法と、コマンド（CLI）で取り込む方法があります。

### 管理画面から取り込む（おすすめ）

sorus を起動したまま、管理画面の **「設定」→「データの取り込み」**（`/admin/import`、または記事がまだ1件も無いときは記事一覧の **「他のサービスから取り込む」**）を開きます。

1. 「他のサービスから取り込む」（取り込み元: `WordPress`）の画面で、必要であれば先に「バックアップを作成してダウンロード」で完全バックアップを保存します。
2. 書き出した `.xml` ファイル（100MB まで）を枠にドラッグ＆ドロップ（またはクリックして選択）します。
3. オプションを選びます。
   - **記事の画像もダウンロードして取り込む（WebP に変換します）**
   - **固定ページ（「会社概要」などのページ）は取り込まない**
   - **記事の著者**: 「すべて自分の記事として取り込む」（既定）か「WordPress の著者ごとにユーザーを作る」かを選べます。新しく作ったユーザーは、そのままではログインできません。管理者が「ユーザー管理」でパスワードを設定してください。
   - **取り込む前に内容を確認する**: 付けたまま **「内容を確認する」** を押すと、データを変えずに記事数・固定ページ数・カテゴリ数・旧 URL からの転送数・警告が表示されます。
4. 確認画面の内容を確かめ、**「この内容で取り込む」** を押すと取り込みが完了します。

### コマンド（CLI）で取り込む

コマンドで取り込む場合、インポート処理はデータベースおよび検索インデックスへ直接一括書き込みを行うため、**sorus サーバーを停止した状態** で実行してください。PC に入れた sorus（デスクトップ版）は、名前 ▼ の「sorus を終了」で終了してから、デスクトップ版の実行ファイルで `sorus import` を実行します（データの置き場所のデータに取り込みます）。

CLI では `--account-mode=current` で管理者のアカウントにまとめ、`--account-mode=authors` で WordPress の著者ごとにユーザーを作ります。既定はどのモードでも `current` です。デスクトップ版で取り込む前に sorus を一度起動して「はじめに」を済ませてください。

### 3.1 事前検証（ドライラン）
いきなりデータベースを変更する前に、XML ファイルが正常に読み込めるかをテストできます。

```bash
sorus import --dry-run path/to/wordpress.xml
```
（Go 開発環境から実行する場合は `go run . import --dry-run path/to/wordpress.xml`）

- 記事数、カテゴリ数、検出された外部画像数、スキップ対象などが画面に表示されます。
- `--dry-run` を指定している間は、データベースやファイルシステムには一切変更が加えられません。

### 3.2 本番インポートの実行
検証結果に問題がなければ、本番インポートを実行します。

```bash
sorus import --download-images=true --timezone=Asia/Tokyo path/to/wordpress.xml
```

インポートが完了すると、以下のような実行サマリーが表示されます：
- 取り込まれた記事数（公開 / 下書き）
- 取り込まれた固定ページ数
- 登録されたカテゴリ数
- 作成されたユーザー数（または「すべて自分の記事として取り込む」を選んだときの著者名）
- ダウンロード・変換された画像数
- 登録された 301 リダイレクト数
- 検索インデックスに登録された記事数

---

## 4. インポート用オプション一覧

`sorus import` コマンドでは、用途に応じて以下のオプションを指定できます。

| オプション | 既定値 | 説明 |
|---|---|---|
| `--download-images` | `true` | 記事内の外部画像を自動ダウンロードし、EXIF 削除および WebP 変換を行ってローカルに保存します。回線が極めて遅い場合や画像を後から手動移行したい場合のみ `false` にします。 |
| `--account-mode` | `current` | `current` は管理者のアカウントにまとめ、`authors` は WordPress の著者ごとにユーザーを作ります。 |
| `--timezone` | `UTC` | GMT 日時が記録されていない古い記事の日時を解釈するタイムゾーンを指定します（日本国内のサイトは `Asia/Tokyo` を推奨）。 |
| `--default-author` | `admin` | `authors` モードで、WordPress 側で著者が未設定の記事を割り当てる sorus ユーザー名です。 |
| `--skip-pages` | `false` | 固定ページ（page）を除外し、ブログ記事（post）のみを取り込む場合に `true` にします。 |
| `--dry-run` | `false` | データベースへの変更をコミットせず、パースと検証のみを実行します。 |

## 5. ステップ 3: 移行後の確認作業

インポートが完了したら、sorus を起動して内容を確認します（デスクトップ版はふだんどおりスタートメニューや「アプリケーション」から起動します）。

```bash
sorus
```

1. **管理画面（`/admin`）での確認**:
   - 記事一覧に過去の記事が取り込まれているか確認します。
   - タイトル、本文、アイキャッチ画像、カテゴリが正しく反映されているか確認します。
   - 固定ページは、記事一覧の「ページ」で確認します。ページには日付とカテゴリは表示されません。
2. **画像表示の確認**:
   - 記事内の画像が破損なく WebP 形式で表示されているか確認します。
3. **URL 転送（301 リダイレクト）の確認**:
   - ブラウザで旧 WordPress の URL（例: `/2023/04/example-post/` や `/?p=123`）にアクセスし、新 URL（`/articles/example-post`）へ自動転送されることを確認します。
   - 固定ページの旧 URL（`/?page_id=123`）は、まず `/articles/<スラッグ>` へ転送され、そこから `/<スラッグ>` へ転送されます。
4. **サイト内検索の確認**:
   - 公開サイトの検索窓から過去記事のキーワードを入力し、正しくヒットするか確認します。

## 6. よくある質問とトラブルシューティング

### Q1. 画像のダウンロードに失敗する画像があります
- **原因**: 旧 WordPress サーバーが停止している、または画像への直接アクセスが制限（Hotlink 保護など）されている可能性があります。
- **対処法**: 旧 WordPress サイトがインターネット上で稼働している状態でインポートを実行してください。失敗した画像は元の URL のまま本文に残るため、必要に応じて後から手動で差し替えることができます。

### Q2. 著者名を特定のユーザーに割り当てたい
- `--account-mode=current` では管理者のアカウントにまとめます。`--account-mode=authors` では WordPress の著者ごとにユーザーを作り、著者が未設定の記事は `--default-author=yamada` のように指定したユーザーへ割り当てます。指定されたユーザーが存在しない場合は、ログインできないライターとして自動作成されます。

### Q3. 固定ページ（お問い合わせ、運営者情報など）を別の方法で作成したい
- `--skip-pages=true` を付けて実行することで、固定ページを無視して投稿記事のみを移行できます。

### Q4. 固定ページのスラッグが sorus の予約語と重なったときは
- 例: `admin` や `search` などのスラッグは、サイトの決まった URL と重なるため使えません。このときは末尾に `-page` を付けたスラッグ（例: `search-page`）で取り込み、警告を出します。旧 URL からの転送は新しいスラッグへ向きます。
- 変更したスラッグは、インポート結果の警告に出ます。

### Q5. WordPress のメニュー（ナビゲーション）は移行されますか
- 移行されません。WordPress のメニュー項目（`nav_menu_item`）は取り込みの対象外です。
- 取り込んだページを使って、sorus の「設定」→「外観」→「サイト構成」でメニューとトップページを組み立て直してください。
