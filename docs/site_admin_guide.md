# サイト管理者ガイド

このガイドは、sorus のサイト管理者（Admin）向けに、サイトの設定、外観・テーマ、公開先への反映、複数人執筆体制とユーザー管理、公開サーバーの運用、AI・MCP 設定、バックアップ、複数サイト管理、WordPress 移行などの操作をまとめたものです。

* sorus をまだ入れていないときは、先に [インストールガイド](install_guide.md) を読んでください。
* 記事や固定ページの執筆、Markdown、画像・ギャラリー、AI 執筆支援、MCP 連携の使い方、校閲フローは [執筆・編集・AI連携ガイド](writing_guide.md) を見てください。
* 公開までの流れを通して知りたいときは、次のどちらかを読んでください。
  * [サーバーを持たずに公開するガイド（静的サイト公開）](static_site_guide.md): ほとんどの人はこちらです。
  * [公開サーバーを使うガイド（公開サーバー連携）](decoupled_sync_guide.md): 公開サーバーを用意できる場合の発展形です。

## 1. 管理画面・設定ハブ・アプリ版の起動と終了

### 上部のメニューと表示言語

| 項目 | 内容 |
| :--- | :--- |
| サイト名 | いま開いているサイトの名前です。サイトが2つ以上あるときはメニュー（サイト名 ▼）になり、サイトを切り替えられます。切り替えたサイトも、同じ sorus のウィンドウの中で開きます（[8章](#8-複数のサイトを使う)）。 |
| ダッシュボード | 記事の状況、閲覧数、週間の人気記事、「サイトに反映」と自動バックアップの状態などをまとめた画面です。 |
| 記事 | 書いた記事とページの一覧です。 |
| 届いた原稿 | 公開サーバーに届いた原稿を受け取り、校閲します。公開サーバーに参加していないときは、参加の案内が出ます。 |
| メディア | アップロードした画像の一覧です。 |
| 設定 | 公開先・サイト設定・バックアップなどの入口です（下の「設定ハブ」）。 |
| ＋ 新しい記事 | 新しい記事を書き始めます。 |
| 名前 ▼ | 自分の名前のメニューです。「表示言語」（JA / EN）、「ログアウト」、「sorus を終了」があります。 |

* 右上の名前 ▼ の **「表示言語」** で、管理画面の言語を JA（日本語）と EN（英語）で切り替えられます。選んだ言語は次からも使われます。
* 「sorus を終了」は、PC に入れた sorus（アプリ版）だけに出ます。押すと sorus そのものが止まります。

### ダッシュボードの画面

ダッシュボードには、ふだんは記事の状況と閲覧数が並び、確かめてほしいことがあるときだけ、いちばん上に案内が出ます。

* **「新しいバージョン（…）があります」**: 新しい版が出たときのお知らせです（[インストールガイドの「更新する」](install_guide.md#6-更新する)）。
* **記事の状況**: 下書き・校閲待ち・予約投稿などの件数です。押すと、その記事の一覧が開きます。
* **「届いた原稿」**: 公開サーバーに届いた原稿を受け取る入口です。公開サーバーに参加しているとき、編集者と管理者に出ます。
* **閲覧数の概要とグラフ、週間の人気記事（上位5件）**: 人気記事のタイトルを押すと、公開サイトのアドレス（基本設定の「公開サイトURL」か、つないでいる公開サーバー）があれば、読者が見ている本番のページを新しいタブで開きます。まだ公開サイトのアドレスが無いときは、この PC の中のページを開きます。
* いちばん下に、**「サイトに反映」** と **「自動バックアップ」** の状態が1行ずつ出ます（管理者だけ）。
  * **「サイトに反映」**: 公開先を設定していると、前回の反映の結果と「サイトに反映」のボタンが出ます（[4章](#4-公開先の設定とサイトに反映)）。公開先をまだ設定していないときは何も出ません。公開先は「設定」→「公開先」で選びます。
  * **「自動バックアップ」**: うまくいっているときは、最後のバックアップの日時と保存先だけが出ます（[7章](#自動バックアップ)）。

次のときは、ダッシュボードのいちばん上に目立つ案内が出ます。

| 案内 | 出るとき |
| :--- | :--- |
| サイトに反映 | 前回の「サイトに反映」に失敗したとき、または sorus を終了している間に予約の時刻を過ぎた記事があるとき。 |
| 自動バックアップ | 保存先のフォルダをまだ選んでいないとき、または最後のバックアップに失敗したとき（PC に入れた sorus だけ）。 |

* 公開サーバーにまだ反映していないサイト設定があるときは、どの画面でも上に「公開サーバーにまだ反映していない設定があります」と出ます。「公開サーバーへ反映する」を押すと送ります。

### 「設定」の画面（設定ハブ）

「設定」を押すと、設定の項目がカードで並びます。このガイドでは、たとえば「設定」→「公開先」のように書きます。

| カード | 内容 |
| :--- | :--- |
| 基本設定 | サイトの名前・説明文・公開サイトのアドレス、公開サイトの多言語対応の ON/OFF、アイコン、アクセス解析などを決めます（[2章](#2-サイト基本設定アクセス解析サーバー版閲覧制限)）。 |
| 外観 | 公開サイトの見た目と、メニュー・トップページの並びを変えます（[3章](#3-外観テーマサイト構成urlと予約スラッグ)）。 |
| 公開先 | サイトを公開する方法を1つ選んで設定します。方法は「① 公開サーバーに接続する」（招待コードで公開サーバーに参加し、記事を送る。[5章](#公開サーバーに参加する招待コード)、[公開サーバーを使うガイド](decoupled_sync_guide.md)）か、「② 静的サイトとして公開する」（記事を HTML に書き出し、Cloudflare Pages やレンタルサーバーに届ける。[4章](#4-公開先の設定とサイトに反映)、[サーバーを持たずに公開するガイド](static_site_guide.md)）のどちらかです。 |
| サイト運用 | 公開サーバーのメンテナンス表示と閲覧制限を切り替えます（[5章](#公開サーバーの閲覧制限パスワードで保護する)）。 |
| AI設定 | 記事エディタで使う AI と API キーを選び、接続を確かめます（[6章](#6-ai設定とmcp管理)）。 |
| カテゴリ | 記事を分類する名前を追加・編集します。 |
| バックアップと復元 | データをまとめて保存し、必要なときにその時点へ戻します（[7章](#7-バックアップと復元)）。 |
| データの取り込み | WordPress などほかのサービスから、記事や画像を取り込みます（[9章](#9-wordpress-からの移行)）。 |
| ユーザー管理 | ログインできる人を追加し、役割を決めます（[5章](#ユーザー管理)）。 |
| サイト | 別のサイトを作ったり、使うサイトを切り替えたりします。PC に入れた sorus だけに出ます（[8章](#8-複数のサイトを使う)）。 |
| MCP連携（「上級者向け」の欄） | ChatGPT・Claude などの AI アプリから、記事を探す・読む・下書きを保存できるようにします（[6章](#mcp-連携の管理)）。 |

* 「公開先」の画面の上には「現在の公開方式」（公開サーバー／静的サイト）が出ます。どちらもまだ設定していないときは、2つの方法から選ぶカードが出ます。もう一方の方式へは、画面の控えめなリンク（「別の公開方法…」）から進めます。
* 「MCP連携」と「AI設定」（ライターは文章スタイルなどの「AI執筆支援設定」）は全員に出ます。「カテゴリ」は編集者と管理者に、そのほかのカードは管理者だけに出ます。
* 各画面の項目の横にある **「?」** を押すと、その項目の説明が吹き出しで出ます。もう一度押すか、`Esc` キーか吹き出しの外を押すと閉じます。

### 起動と終了

PC に入れた sorus（アプリ版）の、起動と終了の動きです。

#### sorus のウィンドウ

* sorus を起動すると、sorus の画面が専用のウィンドウで開きます。アドレス欄やタブの無いウィンドウなので、ほかのサイトのタブに紛れません。
* このウィンドウは、PC に入っている次のブラウザを使って開きます。

  | PC | 使うブラウザ |
  | :--- | :--- |
  | Windows | Microsoft Edge（Windows に最初から入っています） |
  | Mac | Google Chrome、Microsoft Edge、Chromium のどれか（この順に探します） |

* 使えるブラウザが見つからないとき（Chrome も Edge も入っていない Mac など）は、いつものブラウザ（Mac では Safari など）の新しいタブで sorus の画面が開きます。使い方は同じです。タブを閉じたときの動きも、下の「ウィンドウを閉じると終了します」と同じです。
* sorus のウィンドウの中で、公開中の記事のページや ChatGPT・Claude などほかのサイトへのリンクを押すと、いつも使っているブラウザ（OS の既定のブラウザ）で開きます。sorus のウィンドウにタブが増えていくことはありません。
* sorus の管理画面のページ（「公開デザインで確認 ↗」で開く下書きの見た目など）と、サイト名 ▼ で切り替えたほかのサイトは、ログインしたまま使えるよう、sorus のウィンドウの中で開きます。
* すでに起動しているときにもう一度 sorus を起動すると、動いている sorus のウィンドウを開きます。下の「予約をすべて反映してから終了する」を選んだあと、sorus が画面を出さずに動いている間に起動したときも、ウィンドウが開き、自動で終了するのを取りやめます。

#### ウィンドウを閉じると終了します

* sorus の画面をすべて閉じると、ふつうは5秒ほど（通信が途切れたときでも30秒ほど）で sorus が終了します。「公開デザインで確認 ↗」などで開いた sorus の画面も、sorus の画面として数えます。
* ページを移ったり、読み込み直したりしただけでは終了しません。
* 「サイトに反映」やバックアップの途中なら、終わるのを待ってから終了します。
* 起動した直後、sorus の画面が一度も開いていないうちは終了しません。

#### 予約が残っているときの確認

まだサイトに反映していない予約投稿があるときだけ、ウィンドウを閉じると、次のような確認が出ます。数えるのは、公開先（「設定」→「公開先」）を設定したサイトの予約投稿です。

> 予約した記事が 3 件あります（最後は 11月3日 9:00）。sorus を終了すると、その時刻にサイトへ反映されません。

| 答え | どうなるか |
| :--- | :--- |
| 予約をすべて反映してから終了する | sorus は画面を出さずに動き続け、最後の予約をサイトに反映したら自分で終了します。反映に失敗したとき（公開先につながらないなど）は、終了せずに待ち続けます。sorus を起動するとウィンドウが開き、ダッシュボードの「サイトに反映」で結果を確かめられます。 |
| 今すぐ終了する | すぐに終了します。予約の時刻になっても、サイトには反映されません。次に起動したとき、予約の時刻を過ぎていれば、ダッシュボードに「予約時刻を過ぎた記事が N 件あります。サイトに反映しますか？」と出ます。 |

* Windows では、確認のボタンが「はい」と「いいえ」になります。「はい」が「予約をすべて反映してから終了する」、「いいえ」が「今すぐ終了する」です。確認の文にも書いてあります。
* 確認が出ている間にもう一度 sorus を起動してウィンドウが開いたときは、答えを使わずに、そのまま動き続けます。
* 予約投稿が無いとき、まだ公開先を設定していないとき、公開サーバーで予約した記事しかないとき（公開サーバーが時刻を守るため）は、確認は出ずにそのまま終了します。

#### 「sorus を終了」で終了する

右上の名前 ▼ の「sorus を終了」でも終了できます。

* まだサイトに反映していない予約投稿が無いときは、「sorus を終了しますか？」と確認が出ます（サイトが2つ以上あるときは「すべてのサイトを閉じて、sorus を終了しますか？」）。確かめて終了します。
* 予約投稿が残っているときは、件数と最後の予約の日時を示す画面が開き、次の3つから選びます。

  | 選ぶもの | どうなるか |
  | :--- | :--- |
  | 予約をすべて反映してから終了する | 「予約をすべて反映したら、sorus を終了します」と出ます。ウィンドウは閉じてかまいません。sorus は画面を出さずに動き続け、最後の予約をサイトに反映したら自分で終了します。 |
  | 今すぐ終了する | すぐに終了します。予約の時刻にはサイトへ反映されません。 |
  | やめる | 終了せずに、元の画面に戻ります。 |

## 2. サイト基本設定・アクセス解析・サーバー版閲覧制限

「設定」→「基本設定」で、サイト全体に関わる設定を変えます。各項目の横の「?」を押すと、その項目の説明が出ます。

| 項目 | 内容 |
| :--- | :--- |
| サイト名 | ページのタイトル・ヘッダー・フィードに出る名前です。 |
| 公開サイトの多言語対応（英語ページ /en/ を使う） | ON にすると、公開サイトに英語ページ（`/en/`）と言語の切り替えリンクが出て、執筆画面で英語版の作成・AI 翻訳が使えます（[執筆・編集・AI連携ガイド](writing_guide.md#英語版を書く翻訳)）。管理画面の表示言語（右上の名前 ▼ の JA / EN）とは別の設定です。OFF にしても、作った英語版の記事は消えません。公開サーバーにつないでいるときは、保存すると「公開サーバーにまだ反映していない設定」になり、「公開サーバーへ反映する」で公開サーバーにも届きます。 |
| サイト説明文 | 検索エンジンや SNS で出る説明文です。 |
| 公開サイトURL | `https://media.example.jp` のような、公開サイトのアドレスです。SNS で共有したときのリンクや RSS に使います。「公開先」の画面で入れた公開サイトのURLと同じものです。 |
| コピーライト表記 | 公開ページの一番下に出ます。空欄なら「© サイト名」です。 |
| アクセス解析タグ | Cloudflare Web Analytics や Google Analytics 4（GA4）の計測タグ全体を貼ると、公開ページに入ります。測定 ID だけでなく、発行元が示すスクリプト全体を登録してください。 |
| 詳細なアクセス解析の URL | Cloudflare Web Analytics または GA4 の解析画面 URL を入れると、ダッシュボードに「詳細なアクセス解析を開く」ボタンが出ます。タグではなく、解析画面をブラウザーで開いたときの `https://` URL を入力します。 |

入力したら「設定を保存する」を押します。

### アクセス解析タグと解析画面 URL を用意する

Cloudflare Web Analytics または Google Analytics 4（GA4）を使う場合、サービス側でサイトを登録し、表示された計測タグをコピーします。

**Cloudflare Web Analytics**

1. [Cloudflare ダッシュボード](https://dash.cloudflare.com/)で **Analytics & Logs** → **Web Analytics** を開き、**Add a site** を選びます。
2. 公開サイトのドメインを入力して追加します。
3. 対象サイトに表示される JavaScript の計測スニペットをコピーし、公開サイトで計測が始まったことを確認します。
4. Web Analytics で対象サイトの解析画面を開き、その画面の URL をコピーします。

**Google Analytics 4（GA4）**

1. [Google Analytics](https://analytics.google.com/) にログインします。初回はアカウントを作成し、**管理** → **作成** → **プロパティ** から GA4 プロパティを作ります。
2. **管理** → **データ ストリーム** → **ストリームを追加** → **ウェブ** を選び、公開サイトの URL とストリーム名を登録します。
3. ウェブストリームを開き、**Google タグ** → **タグの手順を表示** → **手動でインストール** を選び、表示された `<script>` を含む Google タグ全体をコピーします。`G-` で始まる測定 ID だけでは計測できません。
4. GA4 で対象プロパティのレポート画面（たとえば **レポート** → **リアルタイム**）を開き、その URL をコピーします。

コピーした計測タグを「アクセス解析タグ」へ、解析画面の URL を「詳細なアクセス解析の URL」へ別々に貼り付け、「設定を保存する」を押します。ダッシュボードの「詳細なアクセス解析を開く」ボタンから、登録した画面へ移動できます。静的サイトのアクセス数は sorus 内蔵の集計に含まれないため、このボタンから解析サービスを確認してください。画面の名前や配置は変更されることがあるため、Cloudflare または Google の公式ヘルプで最新の案内も確認してください。

### サイトのアイコン（ファビコン）

ブラウザのタブやブックマークに出るアイコンです。

1. 「設定」→「サイト設定」の「Favicon (サイトアイコン)」を見ます。
2. SVG・PNG・ICO・WebP の正方形の画像（2MB まで）を入れます。
3. 元に戻すときは「デフォルトに戻す（削除）」を押します。

### サイトを準備中のあいだ見せない（サイト閲覧制限・サーバー版）

この項目は、sorus が公開サイトを直接配信するサーバー版の「サイト設定」にあります。

* **アプリ版には、この項目はありません。** sorus のアプリ版は公開サイトをインターネットに直接配信しないためです。以前の版（v0.2.8）の「サイト設定」で閲覧制限を有効にしていても、更新後は働かず、パスワードを求めなくなります。公開サーバーにも送られません。
  * 公開サーバーに参加している場合は、「設定」→「サイト運用」で公開サーバーの閲覧制限を設定します（[5章](#公開サーバーの閲覧制限パスワードで保護する)）。
  * 「サイトに反映」で書き出した静的サイト（Cloudflare Pages など）には、Cloudflare Access を設定します（[手順](static_site_guide.md#公開サイトに閲覧制限を付ける-cloudflare-pages)）。
* サーバー版で以前から有効にしていた閲覧制限は、更新後もそのまま働きます。

サーバー版では、サイトを作っている途中や、関係者だけに先に見せたいときに、そのサーバーの sorus が直接配信している公開サイトで、ユーザー名とパスワードを求めるようにできます（Basic 認証）。

1. 「設定」→「サイト設定」の「サイト閲覧制限（Basic認証）」を見ます。
2. 「公開サイトをパスワードで保護する」にチェックを付けます。
3. 「閲覧用ユーザー名」と「閲覧用パスワード」を入れて、「設定を保存する」を押します。管理画面のログインとは別のパスワードにしてください。
4. 見てもらう人に、サイトのアドレスと、このユーザー名・パスワードを伝えます。公開サイトを開くと、ブラウザがユーザー名とパスワードを尋ねます。

* 保存するとすぐに効きます。誰でも見られるように戻すときは、チェックを外して保存します。
* 管理画面にログインしている人は、入力しなくても公開サイトを開けます。管理画面そのものは今までどおりのログインで使えます。
* 保存したパスワードは画面に出ません。パスワードの欄を空欄のまま保存すると、今のパスワードのままです。変えるときだけ入れ直してください。
* この Basic 認証が機能するのは、そのサーバーの sorus が直接配信している公開サイトだけです。「サイトに反映」で書き出した静的サイト（Cloudflare Pages など）は sorus の Go サーバーを通らないため、この設定では保護されません。Cloudflare Pages などの静的サイトには Cloudflare Zero Trust の Cloudflare Access を設定してください（[手順](static_site_guide.md#公開サイトに閲覧制限を付ける-cloudflare-pages)）。
* 公開サーバーに参加している場合、公開サーバーの公開サイトは公開サーバー上の sorus が配信しています。その閲覧制限は、この「サイト設定」とは別に、「設定」→「サイト運用」で設定します（[5章](#公開サーバーの閲覧制限パスワードで保護する)）。

## 3. 外観・テーマ・サイト構成・URLと予約スラッグ

「設定」→「外観」を開きます。画面の上のタブで「テーマ」と「サイト構成」を切り替えます。テーマを変えてもサイト構成は変わらず、サイト構成を変えてもテーマは変わりません。

### 標準テーマ

公開サイト全体のデザインを選びます。

* **モダン**: シンプルで洗練されたデザイン
* **テック**: コードと等幅の文字を重視した技術ブログ向け
* **ニュース**: 明朝体の見出しと紙面のような配置
* **ポータル**: 濃紺のメニューと白いカードで、情報の多いサイト向け
* **ポートフォリオ**: 作品や活動を写真とともに紹介するサイト向け

1. 各カードの「プレビュー」を押すと、新しいタブで実際のページが開きます。上のバーで「トップ」と「記事」を切り替えられます。プレビューを開いても、公開サイトは変わりません。
2. 「このテーマを適用」を押すと保存されます。
3. 公開サイトに出すには、[サイトに反映](#サイトに反映する) します。公開サーバーを使っている場合は、テーマのタブの下の「公開サーバーへの反映」で「公開サーバーへ反映する」を押します。

### 独自テーマの追加と利用

標準の5つのテーマのほかに、ほかの人が作って公開しているテーマや、自分で作ったテーマ（独自テーマ）を取り込んで使えます。テーマの適用（切り替え）、取り込み、削除は、サイト管理者だけができます。

独自テーマの作り方は [テーマ開発仕様書](theme_development_spec.md) にあります。仕様書の最初にある「ワンショットプロンプト」を AI エージェント（Cursor・Claude Code・GitHub Copilot など）に貼り付けると、テーマを一式作ってもらえます。

**URL から取り込む（GitHub・GitLab）**

1. 「設定」→「外観」→「テーマ」を開き、下の「独自テーマの追加」まで進みます。
2. 「リポジトリ URL から追加」の欄に、テーマのリポジトリの URL を貼り付けます。
   * GitHub の例: `https://github.com/owner/theme-name`
   * GitLab の例: `https://gitlab.com/owner/theme-name`
   * `https://` で始まり `.zip` で終わる Zip の URL も使えます。
3. 「URL から取り込む」を押します。取り込めると、画面の上に「テーマ「（名前）」を取り込みました」と出て、テーマの一覧に「独自テーマ」の印が付いたカードが増えます。カードには「取り込み元」として URL が出ます。

**Zip ファイルから取り込む**

1. 「独自テーマの追加」の「Zip ファイルから追加」で、テーマの Zip ファイル（`theme.json` と `theme.css` を含むもの）を選びます。
2. 「Zip から取り込む」を押します。

**プレビューと適用**

1. 取り込んだテーマのカードの「プレビュー」を押すと、新しいタブで実際のページが開きます。標準のテーマと同じく、プレビューを開いても公開サイトは変わりません。
2. よければ「このテーマを選ぶ」を選んで「このテーマを適用」を押します。
3. 公開サイトに出すには、[サイトに反映](#サイトに反映する) します。独自テーマのファイルもいっしょに書き出されます。自動反映を設定している場合は、適用すると自動で反映が始まります。公開サーバーを使っている場合は、テーマのタブの下の「公開サーバーへの反映」で「公開サーバーへ反映する」を押します（下の「公開サーバーで独自テーマを使う」）。

**テーマを新しくする**

作者がテーマを直したときは、同じ URL（または新しい Zip）をもう一度取り込みます。同じテーマが新しい内容に置き換わります。適用中のテーマでも置き換えられます。置き換えたあとは [サイトに反映](#サイトに反映する) してください。公開サーバーを使っている場合は「公開サーバーへ反映する」を押すと、公開サーバーのテーマも新しい内容に置き換わります。

GitHub のリポジトリ URL（`https://github.com/owner/theme-name`）を指定して取り込んでいる場合は、常に最新の公開内容（main ブランチ）を取り込み、同じテーマ ID で上書き更新されます。タグの Zip（例: `v1.0.0.zip`）を取り込んだ場合はフォルダ名に版が付くため（例: `theme-name-1-0-0`）、別のテーマとして追加されます。

**削除する**

1. 独自テーマのカードの「削除」を押し、「独自テーマ「（名前）」を削除しますか？」の確認で削除を選びます。
2. 適用中のテーマは削除できません（「削除」のボタンが押せません）。先に別のテーマを適用してから削除します。標準の5つのテーマは削除できません。

**注意事項**

* URL から取り込めるのは、誰でも見られる（公開されている）リポジトリと、`https://` の安全な接続の URL だけです。`http://` の URL、ログインが必要なリポジトリ、社内ネットワークなどの内部のアドレスは使えません。
* GitHub・GitLab のリポジトリは、`main` ブランチ（無ければ `master` ブランチ）の内容を取り込みます。
* Zip ファイルは 10MB まで、展開した後の合計は 50MB まで、ファイルは 500 個までです。
* 標準のテーマと同じ名前（`modern`・`tech`・`news`・`portal`・`portfolio`）のテーマは取り込めません。
* 独自テーマは CSS（見た目の指定）と画像・フォントだけでできています。プログラム（JavaScript）は動かないので、取り込んでもサイトのデータが読まれることはありません。それでも、信頼できる作者のテーマを使ってください。
* テーマが外部のサイトのファイル（Web フォントなど）を読み込むようになっている場合や、形式が正しくない場合は、取り込みを止めて理由を表示します。テーマの作者に [テーマ開発仕様書](theme_development_spec.md) に合わせてもらってください。
* AI のアプリとつないでいる場合は、AI に「このテーマを取り込んで適用して」と頼むこともできます（[執筆・編集・AI連携ガイドの「AI のアプリとつなぐ（MCP 連携）」](writing_guide.md#10-ai-のアプリとつなぐmcp-連携)）。

#### 公開サーバーで独自テーマを使う

公開サーバーを使っている場合（公開サーバー連携）も、独自テーマは自分の PC の sorus で取り込んで適用するだけです。公開サーバーにテーマのフォルダを置いたり、公開サーバーを再起動したりする必要はありません。

1. 自分の PC の sorus で独自テーマを取り込み（URL・Zip のどちらでも）、「このテーマを適用」を押します。
2. テーマのタブの下の「公開サーバーへの反映」（または「設定」→「外観」→「サイト構成」、「設定」→「公開先」の「サイト基本設定の反映」）で「公開サーバーへ反映する」を押し、確認で反映します。独自テーマを適用しているときは、確認に「適用中の独自テーマ「（名前）」も、公開サーバーにある同じテーマのファイルを、このPCのテーマのファイルで上書きします」と出ます。
3. 「サイト基本設定・サイト構成と、独自テーマ「（名前）」のファイルを公開サーバーへ反映しました」と出れば完了です。公開サーバーの公開サイトが、そのテーマの見た目になります。

* 送るのは、適用中の独自テーマの `theme.json` と、公開サイトで使うファイル（`theme.css`・画像・フォント）だけです。README などは送りません。送れる大きさは取り込みと同じ（Zip にして 10MB、展開後 50MB、500 ファイルまで）です。
* テーマを新しくしたときは、PC で取り込み直してから、もう一度「公開サーバーへ反映する」を押します。公開サーバーの同じ名前のテーマが、PC の内容に置き換わります。公開サーバーにあった同じ名前のテーマ（以前に手で置いたものを含む）も置き換わります。
* 結果はボタンの下にも残ります。うまくいかなかったときは、表示の最後の文で、公開サーバーがどうなっているかが分かります。

| 表示 | 公開サーバーの状態 | すること |
| :--- | :--- | :--- |
| 「…公開サーバーの設定とテーマは変更していません」「…変更されていません」 | 何も変わっていません | 表示の理由（テーマの形式・大きさなど）を直してから、もう一度反映します |
| 「公開サーバーに反映されたかどうか分かりません」 | 反映されたかもしれず、されていないかもしれません | インターネット接続を確かめて、もう一度「公開サーバーへ反映する」を押します。何度押しても、この PC の設定とテーマで上書きし直すだけです |
| 「サイト基本設定は公開サーバーへ反映しましたが、独自テーマ「（名前）」のファイルを公開サーバーが受け取ったことを確かめられませんでした」 | 設定は変わり、テーマのファイルは古いままかもしれません | 公開サーバーの sorus を更新してから、もう一度反映します |
| 「…前の版も元の場所に戻せませんでした」「…も元に戻せませんでした」 | 設定は変わっていません。このテーマのファイルが無いか新しい版になっていて、公開サイトの見た目が崩れることがあります | もう一度「公開サーバーへ反映する」を押します。この PC の設定とテーマで揃います。続くときは、公開サーバーの空き容量を確かめます |

* 反映の途中で公開サーバーが止まった（停電・再起動など）ときは、公開サイトのテーマの見た目が崩れたり、標準テーマの見た目になったりすることがあります。テーマの元のデータはこの PC にあるので、もう一度「公開サーバーへ反映する」を押せば、この PC の設定とテーマで揃います。
* 公開サーバーのバックアップには、独自テーマのファイルは入りません。公開サーバーを復元したあとは、もう一度「公開サーバーへ反映する」を押してテーマを送り直します。
* 公開サーバーの閲覧制限（パスワードによる保護）は、独自テーマを反映しても変わりません。閲覧制限が有効なら、テーマのファイルもパスワードを知っている人にだけ配信されます。
* 公開サーバーのメンテナンス表示も、独自テーマを反映しても切り替わりません。テーマを入れ替えるあいだ訪問者に途中の見た目を見せたくないときは、反映の前に「設定」→「サイト運用」で手動で始め、反映が終わったら手動で終えてください。メンテナンス表示中は公開サーバーの公開サイトを開いてもメンテナンス画面になるため、見た目はあらかじめこの PC のテーマのプレビューで確かめておきます（[5章の「公開サーバーのメンテナンス表示」](#公開サーバーのメンテナンス表示)）。
* CDN（Cloudflare など）を公開サーバーの前に置いている場合、公開ページが CDN に最大1時間残るため、新しい見た目になるまで時間がかかることがあります。すぐに確かめたいときは CDN のキャッシュを削除してください。

### サイト構成

公開サイトのメニュー、トップページ、トップに並べるページ、トップページのフォトギャラリーを決めます。

**メニュー**

* 公開サイトの上に並ぶ項目です。最大8項目まで足せます。
* 「＋ 行を追加」で足し、「上へ」「下へ」で並べ替え、「削除」で消します。
* 項目の種類は次の4つです。

| 種類 | 選ぶもの | リンク先 |
| :--- | :--- | :--- |
| ページ | 公開中のページ | `/スラッグ` |
| カテゴリ | カテゴリ | `/categories/スラッグ` |
| 記事の一覧 | なし | `/articles` |
| URL | `https://` で始まる外部の URL か、`/` で始まるサイト内の場所 | 入力した URL |

* 表示名は40文字までです。空欄ならページのタイトルかカテゴリ名を使います。URL の項目では表示名が必須です。
* メニューが空のときは、カテゴリの一覧を出します。

**トップページ**

* 「記事の一覧（既定）」なら、トップに新着記事を並べます。
* 公開中のページを選ぶと、トップにそのページの本文を出し、その下に「トップに並べるページ」のカード（最大6件）、新着記事6件、「記事一覧へ」のリンクを並べます。

**トップページのフォトギャラリー**

「トップページのフォトギャラリー」で、メディアライブラリの写真に付けたタグを選ぶか入力し、表示枚数（4・6・8・12・16枚）と見出しを設定します。固定フロントページの有無にかかわらず、タグが付いた写真を新しい順にトップページへ表示します。見出しを空欄にすると「フォトギャラリー」と表示されます。設定したタグの写真がない場合、ギャラリーは表示されません。

静的サイト公開では、サイトを書き出すときにこの PC のメディアライブラリから写真を探し、写真を含む HTML を作ります。公開サーバー連携では、メディアファイルは同期されますが、写真に付けたタグやタグで写真を探すための情報は同期されません。そのため、タグに応じて写真が変わるトップページのギャラリーには静的サイト公開をおすすめします。ギャラリーの設定を保存したあと、静的サイト公開では「サイトに反映」、公開サーバー連携では「公開サーバーへ反映する」を実行してください。

**参照切れの警告**

メニューやトップで選んだページを削除したり非公開にしたりすると、その項目は公開サイトに出なくなり、サイト構成の画面に「確認してください」という警告が出ます。トップに選んだページが使えなくなったときは、トップは記事の一覧に戻ります。

**保存と反映**

「保存する」を押すと、この PC の sorus に保存されます。公開サイトに出すには、[サイトに反映](#サイトに反映する) するか、公開サーバーを使っている場合は「公開サーバーへ反映する」を押します。

### URL と転送

| URL | 内容 |
| :--- | :--- |
| `/` | トップページ |
| `/articles` | 記事の一覧 |
| `/スラッグ` | 公開中のページ |
| `/articles/スラッグ` | 記事 |

* ページを `/articles/スラッグ` で開くと `/スラッグ` へ、記事を `/スラッグ` で開くと `/articles/スラッグ` へ転送します。
* ページのスラッグには、次の言葉を使えません（大文字・小文字は区別しません）。サイトの決まった URL と重なるためです。公開サーバーの同期の窓口の先頭部分（既定では `api`）も使えません。

`admin` `api` `articles` `categories` `search` `static` `uploads` `attachments` `og` `og-image` `feed.xml` `sitemap.xml` `robots.txt` `favicon.ico` `llms.txt` `llms-full.txt` `manifest.json` `sw.js` `healthz`

## 4. 公開先の設定と「サイトに反映」

### 公開先を選ぶ（はじめの1回だけ）

1. 「設定」→「公開先」を開きます。
2. 「公開先を選ぶ」で、次のどれかを選びます。

   | 公開先 | 用意するもの | 内容 |
   | :--- | :--- | :--- |
   | レンタルサーバー | サーバー会社から届いた、ホスト名・ユーザー名・パスワード | SFTP（おすすめ）か FTP で送ります。 |
   | Cloudflare Pages | Cloudflare のアカウント | 無料で使える公開サービスです。画面の案内に沿って「API トークン」を1つ作って貼ります。 |
   | GitHub Pages | GitHub のリポジトリとトークン | 選んだリポジトリのブランチとフォルダへサイトを書き出します。 |
   | Netlify | Netlify のサイト ID とトークン | 選んだサイトへ新しい版を送ります。 |
   | S3 互換ストレージ | バケットとアクセスキー | Cloudflare R2、AWS S3、MinIO などへ直接送ります。静的サイト配信または CDN の設定も必要です。 |
   | フォルダに書き出すだけ | なし | この PC のフォルダにサイトを作ります。できたファイルを自分でアップロードします。 |

3. 選んだ公開先の欄を入力します。くわしい入力のしかたは [サーバーを持たずに公開するガイド](static_site_guide.md#5-公開先を選ぶはじめの1回だけ) にあります。
4. 「接続テスト」を押して、つながることを確かめます。
5. 「保存」を押します。

パスワード、API トークン、S3 のシークレットアクセスキーは、この PC の sorus に保存し、画面には表示しません。
S3 の接続テストでは、バケットに一時ファイルを書き込んでから削除し、公開に必要な権限も確かめます。

### サイトに反映する

記事を公開したり直したりしたら、「サイトに反映」を押します。

1. ダッシュボードの「サイトに反映」、または「設定」→「公開先」の「サイトに反映」を押します。
2. 終わると結果が出ます。うまくいったときは「公開サイトを開く」で、公開されたサイトを確かめられます。

* 送るのは、前の反映から変わったファイルだけです。
* 公開サイトのサイト内検索で使う検索用ファイル（`search-index.json`）も、反映のたびに作り直します。公開した記事がサイト内検索に出ないときは、「サイトに反映」を押します（[運用保守ガイド](operations_guide.md#静的サイト公開の-search-indexjson)）。
* 下書きに戻した記事など、要らなくなったファイルは公開先から消します。消すのは sorus が前に送ったファイルだけで、もともと公開先にあったファイルは消しません。
* 送る画像は、公開中のページで使っている画像（本文・アイキャッチ・ギャラリー・Favicon など）だけ、添付資料は公開中の記事のものだけです。下書きや予約中の記事だけで使っている画像・資料は送りません。この PC の画像・資料の元のファイルは、そのまま残ります。
* Cloudflare Pages では、反映のたびにサイト全体が新しい版に入れ替わります。
* Cloudflare 経由の独自ドメインを使う場合は、公開先画面で「CDNキャッシュ自動クリア（Cloudflare）」を設定できます。Zone ID と Zone / Cache Purge / Purge 権限に絞った API Token を保存すると、反映成功後にキャッシュを消します。Zone ID の場所とトークンの作成手順は[静的サイト公開ガイド](static_site_guide.md#cloudflare-cdn-キャッシュを自動で消す)を参照してください。接続テストはサイト全体のキャッシュをすぐにパージします。
* Cloudflare Pages ではじめて反映するとき、そのプロジェクトにすでに公開中のサイトがあれば、何も送らずに「sorus のサイトで置き換えますか？」と聞きます。置き換えてよいときは「置き換える」を押します。置き換えたくないときは、「公開先」の画面で別のプロジェクト名を入れて保存します。
* 「フォルダに書き出すだけ」ではじめて反映するとき、そのフォルダにすでにトップページ（`index.html`）があれば、何も書き換えずに「sorus のサイトで置き換えますか？」と聞きます。「置き換える」を押すと、トップページなど同じ名前のファイルを上書きします。ほかのファイルは消しません。置き換えたくないときは、空のフォルダか新しいフォルダを指定して保存します。空のフォルダやまだ無いフォルダでは聞きません。2回目からも聞きません。
* 「公開サイトのURL」が空のときや、この PC の中だけのアドレス（`http://127.0.0.1` など）のままのときは、反映せずに止まります。画面に出る「『公開サイトのURL』を入力する」を押して、読者がサイトを開くときのアドレスを入れて保存し、もう一度「サイトに反映」を押します。
* ほかの「お知らせ」が出たときも、内容を読んで直してください。

## 5. 複数人執筆体制・ユーザー管理・公開サーバー運用

### 複数人で書く

複数人でサイトを作る方法は、次の3つです。

| 方法 | 向いているとき | 使い方 |
| :--- | :--- | :--- |
| 公開サーバーとつなぐ（招待コード） | 書く人がそれぞれの PC の sorus で書き、公開サーバーへ届けたい | 招待コードで公開サーバーに参加します。書く人は「公開サーバーへ提出」を押し、編集者は「届いた原稿」で中身と違いを確かめて受け取り、校閲して公開します（[執筆・編集・AI連携ガイド](writing_guide.md#12-記事の保存予約公開サーバーへの提出)）。 |
| 同じネットワークのサーバー版を一緒に使う | 同じ事務所・学校など、同じ LAN・VPN にいる | 1台で管理画面のあるサーバー版（`sorus --server`）を動かし、メンバーはブラウザでその sorus にログインして書きます。アカウントは管理者が「設定」→「ユーザー管理」で作ります。動かし方は [運用保守ガイド](operations_guide.md#デスクトップ版とサーバー版の切り替え) にあります。 |
| AI アプリ（MCP） | AI アプリから記事を探したり、下書きを保存したりしたい | 一人ひとりが自分の権限で AI アプリ（Web・スマホの AI アプリは OAuth 2.1 連携、PC の AI ツールは API トークン）をつなぎます。AI アプリは、つないだ人の役割の範囲で記事を扱います。 |

* どの方法でも、ライターの記事は編集者か管理者が校閲して公開します。

### ユーザー管理

アプリ版とサーバー版のどちらでも、管理者は「設定」→「ユーザー管理」でアカウントを管理できます。

* **追加**: ユーザー名（3〜32文字の半角英数字・ハイフン・アンダースコア）、表示名、初期パスワード（8文字以上）、役割を入力して作ります。ユーザー名とパスワードを本人に伝えてください。
* **役割の変更**: 一覧の役割の欄を選び直すと、その場で保存されます。
* **パスワードの再設定**: 「パスワード変更」で新しいパスワードを決めます。その人はログアウトされ、AI アプリの接続（連携中のアプリと API トークン）も解除されます。AI アプリを使うときは、本人に連携し直すかトークンを発行し直してもらいます。
* **削除**: 削除した人はすぐにログアウトされ、連携していた AI アプリと API トークンも使えなくなります。

事故を防ぐため、自分自身の削除、最後の1人の管理者の削除・降格、記事を書いた人の削除はできません。メンバーが抜けるときは、パスワードを再設定してログインできないようにします。その人の AI アプリの接続も、あわせて解除されます。

### 公開サーバーに参加する（招待コード）

公開サーバーがある場合は、招待コードを使って参加します。準備と全体の流れは [公開サーバーを使うガイド](decoupled_sync_guide.md) にあります。

1. サイト管理者から「招待コード」（`sorus-invite:` で始まる長い文字列）を受け取ります（または発行します）。
2. 「設定」→「公開先」を開きます。
3. 「招待コード」の欄に、受け取ったコードを全部そのまま貼り付けます。
4. 「接続を確かめて参加する」を押します。「いまの接続」に、接続先・名前・立場・有効期限が出れば参加できています。

### 公開サーバーの閲覧制限（パスワードで保護する）

公開サーバーの公開サイトを、閲覧用のユーザー名とパスワードを知っている人だけが見られるようにできます。これは**公開サーバー自身の設定**です。

* PC に入れたアプリ（デスクトップ版）の「サイト設定」には閲覧制限はありません。管理画面のあるサーバー版の「サイト設定」の閲覧制限（[2章](#サイトを準備中のあいだ見せないサイト閲覧制限サーバー版)）とは別の設定で、互いに影響しません。
* 公開サーバーの設定は公開サーバーに保存され、そこにつないでいるすべての PC で共通です。
* 「サイトに反映」や「公開サーバーへ反映する」（サイト基本設定の反映）では変わりません。「設定」→「サイト運用」の画面で「公開サーバーに保存する」を押したときだけ変わります。
* 操作できるのは、サイト管理者の招待で参加している人だけです。ライターや編集者の招待では、この欄は出ません。

#### いまの状態を確かめる

1. 「設定」→「サイト運用」を開き、「公開サーバーの閲覧制限（Basic認証）」を見ます。画面を開くと、公開サーバーに問い合わせて、いまの状態を表示します。
2. 「公開サーバーの設定」の欄に、「有効（パスワードを求める）」「無効（誰でも見られる）」「有効に設定されているが、働いていない」のどれかが出ます。パスワードは「設定済み」か「未設定」かだけが出て、中身は表示されません。
3. 「外からの確認」の欄に、この PC から公開サイトのアドレスをパスワードなしで開いた結果が、URL ごとに出ます。開くのは、トップページと、フィード（`/feed.xml`）・最新の記事・公開中の画像1枚だけです。公開サーバーの URL と、公開サーバーに設定された「公開サイトURL」（CDN を通した URL など）が違うときは、両方で開きます。
   * 「パスワードを求められました」: その URL はパスワードを求めました。
   * 「パスワードなしで表示されました」: その URL は誰でも見られます。
   * 「確かめられませんでした」: 接続できない、別の URL へ転送された（転送先は開きません）、エラーが返った、のどれかです。
   * 「確かめていません」: 公開サイトURL がインターネットに公開されていないアドレス（この PC の中や社内のアドレス）を指している、または URL の形式が正しくないため、開きませんでした。

   これはこの PC から一部の URL を開いた結果です。一覧にないほかの記事や画像、`http://` など別のアドレスで開いた場合、インターネット上のほかの経路は確かめていません。
4. 画面の上の案内で、総合の状態が分かります。

| 画面の案内（抜粋） | 意味 | 次にすること |
| :--- | :--- | :--- |
| 確かめた URL（下の一覧）は、すべてパスワードを求めました。ただし、確かめたのは一覧の URL だけです。 | 有効で、一覧の URL はパスワードを求めた。一覧にないほかの記事・画像や、CDN に残っている以前のキャッシュは確かめていない | CDN を使っているときは、CDN のキャッシュを削除（パージ）する。そのあと、ブラウザのプライベートウィンドウでいくつかの記事と画像を開き、パスワードを求められるか確かめる |
| 公開サーバーでは有効ですが、確かめられなかった URL があります。保護されているとは言い切れません。 | 有効だが、接続できない・転送された・公開されていないアドレスなどで、確かめられなかった URL がある | 少し待って「状態を確かめる」を押す。または、ブラウザのプライベートウィンドウで公開サイトの記事や画像を開く。「公開されていないアドレス」と出るときは、公開サーバーの「公開サイトURL」を確かめる |
| 公開サーバーでは有効ですが、パスワードなしで表示される URL があります。 | CDN のキャッシュなどで、パスワードなしに見えるURLがある | CDN のキャッシュを削除（パージ）してから「状態を確かめる」を押す |
| 有効に設定されていますが、閲覧用のユーザー名かパスワードが無いため働いていません。 | 有効だが、ユーザー名かパスワードが無いため誰でも見られる | ユーザー名とパスワードを入れて保存し直す |
| 閲覧制限は無効です。公開サイトは誰でも見られます。 | 無効 | なし |
| 公開サーバーの閲覧制限の状態が分かりません。保護されているとは限りません。 | 公開サーバーに問い合わせられない、または応答を読めない | 「状態を確かめる」を押す。それでも分からなければ、公開サーバーの URL と接続を確かめる |

#### 有効にする・パスワードを変える

1. 「公開サーバーの公開サイトをパスワードで保護する」にチェックを付けます。
2. 「閲覧用ユーザー名」を入れます（100文字まで。「:」（コロン）と制御文字は使えません）。
3. 「閲覧用パスワード」を入れます（72バイトまで）。すでにパスワードが設定されているときは、空欄のまま保存すると今のパスワードのままです。変えるときだけ入れ直してください。管理画面のログインとは別のパスワードにしてください。
4. 「公開サーバーに保存する」を押します。

* 有効にするには、ユーザー名とパスワードの両方が必要です。
* 保存すると、公開サイトを外から開いて確かめた結果が案内に出ます。「確かめた URL（下の一覧）は、すべてパスワードを求めました」と出ても、確かめたのは一覧の URL だけです。CDN を使っている場合は、CDN のキャッシュを削除（パージ）し、プライベートウィンドウでいくつかの記事と画像を開いて、パスワードを求められることを自分でも確かめてください（下の「CDN と以前のキャッシュの限界」）。
* パスワードを変えたあとは、古いパスワードは使えません。見てもらう人に新しいパスワードを伝え直してください。
* 保存したパスワードは画面にもログにも出ません。

#### 無効にする（誰でも見られるように戻す）

1. 「公開サーバーの公開サイトをパスワードで保護する」のチェックを外します。
2. 「公開サーバーに保存する」を押し、確認の画面で了承します。
3. 「閲覧制限は無効です。公開サイトは誰でも見られます。」と出れば完了です。

無効にすると、公開サイトは誰でも見られるようになります。もう一度有効にするには、ユーザー名とパスワードを入れて保存し直します。

#### 保存できなかったとき

| 画面の案内（抜粋） | 意味 | 次にすること |
| :--- | :--- | :--- |
| 公開サーバーの状態を読み込んでから保存してください。 | 状態を読み込む前に保存しようとした | 「状態を確かめる」を押してから、もう一度入力する |
| ほかの PC で公開サーバーの閲覧制限が変更されていたため、保存しませんでした。 | ほかの PC が先に変えた。何も変わっていない | 表示された最新の状態を確かめてから、保存し直す |
| 公開サーバーの URL が https:// で始まらないため、閲覧制限を変更できません（何も変更していません）。 | 公開サーバーの URL が https:// でない（この PC の中の `http://localhost` を含む）。閲覧用のパスワードは暗号化されない接続には送らない | 公開サーバーの URL を https:// で始まるものにする |
| 公開サーバーの sorus が、この接続を https で直接受けていないため、閲覧制限を変更できません（何も変更していません）。 | 公開サーバーの sorus が https を直接受けていない。前段のプロキシや CDN（同じサーバーの nginx なども含む）で https を終え、sorus までを http でつないでいる | 公開サーバーの sorus が https を直接受ける構成（`AUTOCERT_DOMAIN` を設定）にする（[公開サーバーを使うガイド](decoupled_sync_guide.md#公開サイトをパスワードで保護する)） |
| 閲覧制限は変更していません（公開サーバーに送っていません）。 | 保存の前に公開サーバーの状態を確かめられなかったため、変更を送らなかった。何も変わっていない | 「状態を確かめる」を押し、接続できることを確かめてから、保存し直す |
| 変更が反映されたかどうか分かりません。 | 変更を送った後に応答が無い、または読めなかった | 「状態を確かめる」を押して、いまの状態を確認する |
| 公開サーバーの応答を読み取れませんでした。 | 公開サーバーの URL が違う可能性がある | 公開サーバーの URL が sorus の公開サーバーか確かめる |

「状態を確かめる」を押しても表示が変わらないときは、この PC から公開サーバーに接続できているかを確かめてください（「いまの接続」の欄の接続先）。

公開サーバーの URL が https:// でないときと、公開サーバーの sorus が https を直接受けていないときは、画面を開いた時点で、保存の欄の上に変更できない理由が出て、保存の欄は使えなくなります。いまの状態の確認はできます。このとき、この PC は閲覧用のパスワードを公開サーバーに送りません。

#### 接続に失敗したとき

* 公開サーバーに問い合わせられないときは、「公開サーバーの閲覧制限の状態が分かりません。保護されているとは限りません。」と表示されます。保護されているとは表示されません。
* この表示を、保護されていると思い込まないでください。接続できるようになってから「状態を確かめる」を押してください。
* 記事の提出・公開などの同期は、閲覧用のパスワードが無くても今までどおり招待で行えます。閲覧制限の設定が同期を止めることはありません。

#### CDN と以前のキャッシュの限界

* 「外からの確認」で開くのは、トップページ・フィード・最新の記事・画像1枚だけです。すべてパスワードを求めても、CDN に残っているほかの記事や画像のキャッシュが無いことまでは確かめていません。
* 公開サーバーの前に Cloudflare などの CDN を置いている場合、閲覧制限を有効にする前に CDN に保存されたページや画像は、パスワードなしで配られ続けることがあります。有効にしたあとは、CDN のキャッシュを削除（パージ）してください。
* sorus は CDN の設定を変えません。CDN のキャッシュ削除は、CDN の管理画面で行ってください。
* 閲覧制限は、公開サーバーが応答する公開サイトにかかります。「サイトに反映」で書き出した静的サイト（Cloudflare Pages など）にはかかりません。
* すでに公開されて読まれた内容や、パスワードを知った人が保存した内容は、この設定では取り消せません。
* 閲覧用のパスワードは、https で暗号化された接続でだけ送られます（この PC の中の `http://localhost` にも送りません）。公開サーバーの sorus も、自分で https を直接受けた接続でだけ受け取ります。ただし、閲覧用のパスワードは見てもらう全員で共有するものです。人ごとに別のパスワードを付けることはできません。

### 公開サーバーのメンテナンス表示

公開サーバーの公開サイトを一時的に止め、訪問者にはメンテナンス画面を表示できます。テーマの入れ替えや記事の大きな整理のあいだ、途中の状態を見せたくないときに使います。標準の「ただいまメンテナンス中です」の画面のほか、エンジニアが用意した 1 つの HTML ファイルを使うこともできます。

* メンテナンス画面はテーマに関係なく、HTTP のステータスは 503（一時的に利用できない）です。検索エンジンには「一時的に止まっている」と伝わります。
* **始めるのも終えるのも手動**です。自動では終わりません。テーマの反映などと連動して始まったり終わったりもしません。
* **ON/OFF は公開サーバーに保存**され、公開サーバーを再起動しても続きます。そこにつないでいるすべての PC で共通です。
* **独自の HTML は、この PC のこのサイトに保存**します。選んで保存しただけでは公開サーバーは変わりません。始めるときに、いま選んでいる画面を公開サーバーへ送ります。内容の編集画面はありません（エンジニアが用意したファイルを選ぶだけです）。CSS や画像は、その HTML ファイルの中に入れてください（上限 1MB、UTF-8）。
* 「公開サーバーへ反映する」（テーマ・サイト設定の反映）や、閲覧制限の保存では切り替わりません。独自の画面もテーマとは別です。
* 操作できるのは、サイト管理者の招待で参加している人だけです（デスクトップ版でも、管理画面のあるサーバー版でも同じです）。ライターや編集者の招待では、この欄は出ません。
* メンテナンス表示中も、記事の提出・公開・予約・取り込みなどの同期は今までどおり使えます。

#### 画面を選ぶ（この PC）

1. 「設定」→「サイト運用」の「この PC で使う画面」で、HTML ファイルを選び「この PC に保存」を押します。保存できた案内が出ても、公開サーバーはまだ変わっていません。
2. 標準の画面に戻すときは「標準の画面に戻す」を押します。これも、この PC の選択だけが変わります。
3. 独自の HTML を選んでいないときは、始める前に「標準の画面を使いますか」と確認します。

この PC のバックアップには、このサイトで選んだ HTML が含まれます。公開サーバーのバックアップには、いまの ON/OFF と、公開サーバーに保存した画面が含まれます。復元すると、それぞれ保存されていた内容に戻ります。

#### 始める・終える・画面を反映

1. 「設定」→「サイト運用」を開き、「公開サーバーのメンテナンス表示」を見ます。画面を開くと公開サーバーに問い合わせ、「公開サーバーの状態」に「メンテナンス表示中（訪問者に HTTP 503）」か「オフ（通常の配信）」が出ます。「公開サーバーの画面」には、公開サーバーがいま出している画面（または表示していないこと）が出ます。この PC で選んでいる画面とは別に表示します。
2. 始めるときは「メンテナンス表示を始める」を押し、確認の画面で了承します。いまこの PC で選んでいる画面が、公開サーバーの ON といっしょに反映されます。
3. 表示中に別の HTML を使いたいときは、この PC に保存してから「画面を反映」を押します。ON/OFF は変わりません。選んだだけでは公開サーバーは変わりません。
4. 終えるときは「メンテナンス表示を終える」を押します。「メンテナンス表示を終えました」と出れば、公開サイトは通常どおり表示されます。

* 画面の状態は、押したときに公開サーバーから返ってきた状態です。ほかの PC がすでに同じ状態にしていたときは「すでに…（何も変更していません）」と出ます。すでに表示中のときに「始める」を押しても、ほかの PC が送った画面は上書きしません。上書きするときは「画面を反映」を使います。
* 表示中かどうかを自分の目でも確かめるときは、ブラウザのプライベートウィンドウで公開サイトを開いてください。

| 画面の案内（抜粋） | 意味 | 次にすること |
| :--- | :--- | :--- |
| 公開サーバーはメンテナンス表示中です。 | 訪問者にメンテナンス画面（HTTP 503）を返している | 作業が終わったら「メンテナンス表示を終える」を押す。画面を変えたいときは「画面を反映」 |
| メンテナンス表示はしていません。 | 通常どおり配信している | なし |
| この PC で選んでいる画面と、公開サーバーが表示している画面が違います。 | この PC の選択と、公開サーバーが出している画面が違う（ほかの PC が先に反映した、など。中身が同じならファイル名が違っても一致と出ます） | 「画面を反映」を押す（ON/OFF は変わらない）。この PC の選択を変えるだけなら保存する |
| 独自の画面は反映されていません。 | 送った画面と違う画面が返ってきた | 表示中の状態を確かめる |
| 公開サーバーのメンテナンス表示の状態が分かりません。 | 公開サーバーに問い合わせられない、応答を読めない、または切り替えの結果が分からない | 「状態を確かめる」を押す。それでも分からなければ、公開サーバーの URL と接続を確かめる |
| 切り替えが反映されたかどうか分かりません。 | 切り替えを送った後に応答が無い・読めない・公開サーバーでエラーが起きた。切り替わったかもしれず、切り替わっていないかもしれない | 「状態を確かめる」を押して、いまの状態を確認する。違っていれば、もう一度押す（何度押しても、指定した状態になるだけです） |
| メンテナンス表示は切り替わっていません。 | 公開サーバーが断った（招待の期限切れ・権限が無いなど）。何も変わっていない | 表示の理由を確かめる |
| 公開サーバーの状態が切り替わっていません。 | 公開サーバーが、押した操作と違う状態を返した | 表示中の状態を確かめてから、もう一度押す |

切り替えに失敗したとき、この PC は自動ではやり直しません。表示を成功と思い込まず、「状態を確かめる」で公開サーバーのいまの状態を確かめてください。

#### メンテナンス表示で止められないもの

* メンテナンス画面は、公開サーバーの sorus が配信する公開サイトにだけ表示されます。
* 公開サーバーの前に Cloudflare などの CDN を置いている場合、始める前に CDN に保存されたページや画像は、CDN のキャッシュが切れるか削除（パージ）するまで表示され続けることがあります（公開ページは最大1時間、画像はもっと長く残ります）。すぐに止めたいときは、始めたあとに CDN の管理画面でキャッシュを削除してください。sorus は CDN の設定を変えません。
* メンテナンス画面自体は、CDN やブラウザに保存させない指定（`Cache-Control: no-store`）で返します。終えたあとに古いメンテナンス画面が残ることは通常ありません。
* 公開サーバーが停止している・接続できないときは、メンテナンス画面も表示されません（この機能は公開サーバーの sorus が動いているときにだけ働きます）。
* 「サイトに反映」で書き出した静的サイト（Cloudflare Pages など）にはかかりません。
* 閲覧制限（パスワードによる保護）を有効にしているときは、公開サイトのページや画像を開くと先にパスワードを求めます。パスワードを知らない人には今までどおりパスワードの入力画面が出て、パスワードを入れた人にメンテナンス画面が表示されます。
* 管理画面のあるサーバー版で同期を受けているサーバーでは、その管理画面にログイン中の人は、メンテナンス表示中も公開サイトを通常どおり見られます（ログインしていない訪問者にはメンテナンス画面が出ます）。
* 公開サーバーの稼働の監視（`/healthz`）は、メンテナンス表示中も今までどおり応答します。

この PC が使えなくなってメンテナンス表示を終えられないときは、公開サーバーで `sorus token create` を実行してサイト管理者の招待を発行し、別の PC から参加して「メンテナンス表示を終える」を押してください（[公開サーバーを使うガイド](decoupled_sync_guide.md)）。

## 6. AI設定とMCP管理

### AI を設定する（「設定」→「AI設定」）

サイトの管理者が「設定」→「AI設定」で、使う AI と API キーを登録します。保存するとすぐに使えるようになり、sorus を起動し直す必要はありません。

1. 使う AI を選びます。Gemini（Google AI Studio・無料枠あり）、OpenAI 互換（OpenAI の API）、Claude（Anthropic）、ローカルLLM・その他の互換API（Ollama・LM Studio など）から選べます。
2. 各社の画面で発行した API キーを貼り付けます。Gemini のキーは `AQ.` または `AIza` で始まる文字列です。ローカルLLM ではキーは不要で、代わりにベースURL（例: `http://localhost:11434/v1`）を入力します。
3. モデルはふだん空欄のままで構いません（Gemini の既定は `gemini-3.8-flash`。見つからないときは `gemini-3.5-flash-lite` を使います）。
4. 「接続テストを実行」を押すと、入力中の設定で短い文章のタイトル案を作ってもらい、応答までの時間を表示します。保存する前に確かめられます。
5. 「保存する」を押します。

* 保存したキーは画面には先頭と末尾だけを表示します。変えないときはキーの欄を空欄のまま保存します。
* キーの欄を空欄のまま保存すると、環境変数（`GEMINI_API_KEY` など）のキーがあればそれを使います。使う順番は「この画面で保存したキー」→「環境変数のキー」です。
* 別の AI やベースURLに切り替えたときは、保存済みのキーをそこへ送りません。新しいキーを入力してください。
* 「この画面の設定を消して、環境変数の設定に戻す」を押すと、環境変数の設定で動くようになります。
* 関連記事や AI の過去記事の参照（AI 検索）のために外部の AI に送るのは、公開中の記事の本文だけです。下書き・校閲待ち・予約中の記事は送りません（AI 検索の設定は[運用ガイドの環境変数一覧](operations_guide.md#5-技術者向け付録-環境変数一覧)）。
* 「AIのAPIキーが無効または未認可です」と出たときは、キーが正しいか、Google AI Studio でキーが有効になっているかを確かめてください。原因の詳しい内容は動作の記録（`sorus.log`）に残ります。

### MCP 連携の管理

「設定」→「MCP連携」では、AI アプリ（ChatGPT・Claude・Gemini・Perplexity など）や PC の AI ツール（Claude Desktop・Claude Code・VS Code・Cursor・GitHub Copilot CLI など）との接続を管理します。接続手順や使い方の詳細は [執筆・編集・AI連携ガイドの「AI のアプリとつなぐ（MCP 連携）」](writing_guide.md#10-ai-のアプリとつなぐmcp-連携) を見てください。

管理者として把握しておくポイントは次のとおりです。

* **権限の範囲**: AI アプリが操作できる範囲は、連携を許可した（またはトークンを発行した）ユーザーの役割に従います。テーマの取り込み・切り替え・削除は、サイト管理者の権限でのみ実行できます。
* **全員のトークン管理**: 管理者は全員の MCP トークンを管理でき、不要になったトークンは「失効」で即座に無効化できます。
* **OAuth 2.1 連携の取り消し**: Web・スマホの AI アプリは「連携中のアプリ」（または「公開サーバーの連携中のアプリ」）の「取り消す」で接続を止められます。
* **公開サーバーの同意画面**: 公開サーバーで OAuth 2.1 連携を許可するときは、「公開サーバーの MCP 連携」の「確認コードを表示」（8文字、10分間・1回有効）を使います。
* **パスワード変更・削除・招待取消時の連動**: ユーザーのパスワードを変更・再設定したり、ユーザーを削除したり、公開サーバーの招待を取り消したりすると、紐づく連携中のアプリ（OAuth）と API トークンも解除・無効化されます。

## 7. バックアップと復元

PC に入れた sorus では、**その PC の中のデータがすべての原本**です。PC が壊れても困らないよう、自動バックアップを設定してください。

### 自動バックアップ

保存先のフォルダを1回選ぶと、sorus を起動したときと、動いている間は1日1回、そのフォルダにバックアップを置きます。

1. 「設定」→「バックアップと復元」を開きます（ダッシュボードの「バックアップ先を選ぶ」からも開けます）。
2. 「自動バックアップ」で保存先を選びます。
   * OneDrive・Google ドライブ・Dropbox のフォルダが見つかったときは、「（サービス名） に保存する」のボタンが出ます。押すと、その中に「sorus バックアップ」フォルダを作って保存します。
   * 見つからないときや別の場所にしたいときは、「フォルダの場所を入力する」にフォルダの場所を入力して「ここに保存する」を押します。フォルダが無ければ作ります。
3. ダッシュボードの「自動バックアップ」に、最後のバックアップの日時と結果が出ます。

* 新しいものから14個を残し、それより古いものは消します。
* OneDrive などの同期フォルダを選ぶと、バックアップがインターネット上にも保存されるので、PC が壊れても安心です。
* 今すぐ取りたいときは「今すぐバックアップする」、やめるときは「自動バックアップをやめる」を押します（作ったバックアップは消えません）。

自動バックアップにも、パスワードや API キーなどの秘密情報が含まれるため、人に渡さないでください。サイトを渡すときは「今のサイトを Zip ファイルでダウンロード」を使ってください。

### 手動でバックアップを作る

「設定」→「バックアップ」の「バックアップを作成してダウンロード」を押すと、記事・設定・アカウント・画像・添付資料をまとめた Zip ファイル（`sorus_backup_日時.zip`）がダウンロードされます。このバックアップには、パスワードや API キーなどの秘密情報が含まれるため、人に渡さないでください。サイトを渡すときは「今のサイトを Zip ファイルでダウンロード」を使ってください。

### バックアップから復元する

1. 「設定」→「バックアップ」の「バックアップから復元」に、Zip ファイルをドラッグ＆ドロップします。
2. 「このバックアップから復元する」を押し、確認で「内容を理解したうえで復元します」にチェックを入れて「復元する」を押します。
3. 復元が終わるとログアウトされます。バックアップを作ったときのアカウントでログインします。

* 壊れたファイルや sorus のバックアップではないファイルを選んだときは、何も変えずにエラーを出します。
* 復元すると、サイト内検索の索引（`search_index`）も、復元した記事に合わせて作り直します。静的サイト公開の公開先の検索は、次に「サイトに反映」したときに揃います。
* 取り込んだ独自テーマはバックアップに入りません（復元してもいまの独自テーマはそのまま残ります）。新しい PC に引っ越したときは、取り込み元の URL・Zip からもう一度取り込みます。
* 新しい PC に引っ越すときは、「はじめに」の画面の「バックアップから始める」を使います（[インストールガイド](install_guide.md#前の-pc-のデータを引き継ぐとき)）。

## 8. 複数のサイトを使う

PC に入れた sorus（アプリ版）では、1つの PC で複数のサイト（たとえば「サイトA」と「サイトB」）を作って使い分けられます。サイトごとに、記事・ページ・画像・添付・設定・外観（テーマ）・公開先・自動バックアップの設定がすべて分かれています。

### 2つ目のサイトを作る

1. 「設定」→「サイト」を開きます。
2. 「新しいサイトを作る」を押します。
3. 同じウィンドウで、新しいサイトの「はじめに」の画面に切り替わります。
4. 1つ目のサイトと同じように、あなたの名前とパスワード、サイト名（例: 「サイトB」）を決めて「はじめる」を押します（「バックアップから始める」も使えます）。

* **名前とパスワードはサイトごとに別です。** サイトごとに「はじめに」でユーザー名とパスワードを決め、サイトごとにログインします。「パスワードを忘れたとき」の再設定もサイトごとに行います。
* **「はじめに」をもう一度試したいとき**: 「新しいサイトを作る」で新しいサイトを作って試し、試し終えたらそのサイトを削除してください。いま使っているサイトには影響しません。

### サイトを切り替える

* **サイトが2つ以上あるときだけ**、画面の左上のサイト名（例: 「サイトA ▼」）がメニューになります（サイトが1つだけのときは、これまでと同じ表示です）。
* 左上のサイト名を押すと、すべてのサイトの名前と「サイトの一覧と追加」（「設定」→「サイト」へのリンク）が並びます。
* 別のサイトを選ぶと、そのサイトの画面に切り替わります。まだそのサイトにログインしていなければ、そのサイトのログイン画面が出ます。
* サイトを切り替えても、ウィンドウは増えません。同じウィンドウの中で切り替わります。ウィンドウの題名にも、いま開いているサイトの名前が出ます。
* 「設定」→「サイト」の「サイトの一覧」にある「開く」からも切り替えられます。

### 起動している間の動きと終了

* **すべてのサイトが同時に動きます。** sorus が起動している間は、いま画面で開いていないサイトでも、予約投稿の時刻になれば自動で公開先に反映し、自動バックアップもサイトごとに動きます（複数のサイトで自動バックアップに同じフォルダを選んでも、互いのバックアップを消すことはありません）。
* sorus を起動すると、すべてのサイトを開き、**最後に使っていたサイト**を sorus のウィンドウで開きます。すでに起動しているときにもう一度起動しても、最後に使っていたサイトが開きます。
* データの破損などで開けなかったサイトがあっても、ほかのサイトは開きます。開けなかったサイトは「設定」→「サイト」の一覧に、分かりやすい理由（データが壊れている、フォルダやファイルが見つからない、読み書きできない、アドレスを使えない、など）と、そのサイトのフォルダの場所が出ます。技術的な詳しい内容は「詳しい内容」を開くと見られます。詳しい記録（`sorus.log`）の場所も出ます。
* 開けなかったサイトを一覧から外すときは、開いているサイトの「設定」→「サイト」で「一覧から外す」を押します。確認では、フォルダの場所と、そのフォルダの中のデータはそのまま残ることを示します。一覧の記録から外すだけで、フォルダも中のデータも消しません。外したあとは、それらをそのままの場所に残したことを知らせます。このサイトのバックアップ（自動バックアップで作った Zip など）があれば、新しいサイトの「はじめに」で「バックアップから始める」を選ぶと戻せます。サイトが1つだけ残っているときは外せません。
* sorus の画面をすべて閉じたとき、または右上の名前 ▼ から「sorus を終了」を押したときは、**すべてのサイトが閉じて sorus が止まります。** 「sorus を終了」では「すべてのサイトを閉じて、sorus を終了しますか？」と確認が出ます。
* 終了のときの予約の確認（[1章の「予約が残っているときの確認」](#予約が残っているときの確認)）は、すべてのサイトのまだ反映していない予約投稿を合わせて数えます。

### サイトを削除する

削除したいサイトにログインしてから操作します（ほかのサイトからは削除できません。また、開いているサイトが1つしか残っていないときは削除できません）。

1. 削除したいサイトを開き、ログインします。
2. 「設定」→「サイト」を開き、下にある「このサイトを削除」を押します。
3. 確認画面で、消えるものとバックアップを作る場所を確かめます。
   * **消えるもの**: このサイトの記事・画像・添付・設定・公開先の設定・招待が、この PC の sorus から消えます。公開先にすでに公開したサイトは消えません。
   * **バックアップを作る場所**: 削除の直前に完全バックアップ（`sorus_deleted_site_` で始まる .zip ファイル）を必ず作ります。そのサイトで自動バックアップの保存先フォルダを設定していればそのフォルダに、設定していなければデータの置き場所の中の「削除したサイトのバックアップ」フォルダに保存します。保存先のフォルダが、削除で消えるデータの中にあるときは、バックアップまで消えないよう「削除したサイトのバックアップ」フォルダに保存します。バックアップの作成に失敗したときは、何も消さずに中止します。
4. 確認のため、サイト名（例: 「サイトB」）をそのまま入力し、「削除する」を押します（サイト名が一致したときだけ押せます）。
5. 削除が終わると、バックアップを保存した場所が表示され、残っている先頭のサイトが開きます。

* **削除したサイトを元に戻すとき**: 「設定」→「サイト」→「新しいサイトを作る」で新しいサイトを開き、「はじめに」の画面の下にある「バックアップから始める」で、削除の直前に作られたバックアップファイルを選んで元に戻せます。独自テーマのファイルはバックアップに含まれません。削除する前に、取り込み元の URL または Zip を保管してください。新しいサイトに復元したあと、そのサイトでテーマが見つからない場合は、保管した URL または Zip から再登録してください。

### 「はじめに」が済んでいないサイトを続ける・削除する

* 「新しいサイトを作る」を押したあと、「はじめに」を済ませないまま別のサイトに切り替えたり sorus を終了したりしたサイトも、「設定」→「サイト」の一覧に「名前の無いサイト（作成日）」（「はじめに」がまだ済んでいません）として残ります。
* 続きから始めるときは、一覧の「開く」を押します。
* 要らないときは、別のサイトの「設定」→「サイト」の一覧にある「削除」を押し、確認で削除できます（まだサイト名を決めていないため、サイト名の入力は要りません）。

## 9. WordPress からの移行

WordPress の記事・カテゴリ・画像・URL の転送を、sorus に引き継げます。

* タイトル・本文・公開日時・スラッグを移し、HTML を Markdown に変換します。
* 記事の中の画像をダウンロードし、位置情報を消して WebP に変換します。
* 古い URL（`/2023/04/example/` や `/?p=123` など）から新しい URL への転送を登録します。
* 管理画面の「設定」→「データの取り込み」（記事がまだ無いときは記事一覧の「他のサービスから取り込む」）から、書き出したファイル（`.xml`）を選んで取り込めます。「すべて自分の記事として取り込む」（既定）か「WordPress の著者ごとにユーザーを作る」かを選べます。

手順は [WordPress 移行ガイド](wordpress_migration_guide.md) を見てください。

## 10. 技術者向け付録

### サーバー版のログイン

サーバー版（Docker・systemd などで管理画面を動かす場合）の最初の管理者のユーザー名は `admin` です。パスワードは次のとおりです。

| 環境 | パスワード |
| :--- | :--- |
| 開発用（`make dev`） | `dev-admin-pass` |
| 本番 | 環境変数 `ADMIN_PASSWORD` の値。未設定なら自動で作り、はじめて起動したときのログに出します。 |

### コマンドでの書き出しとバックアップ

コマンドでの静的書き出し（`sorus export`）、バックアップ（`sorus backup`）、復元（`sorus restore`）、サイトの一覧（`sorus sites`）は [運用保守ガイド](operations_guide.md) を見てください。

### サイト内検索の索引を作り直す

sorus が配信するページのサイト内検索（`/search`）は、記事の索引（`search_index`）を使います。記事を保存・公開・予約公開・ゴミ箱へ移す・削除したときは、その記事を自動で索引に反映します。sorus を起動したときとバックアップを復元したときは、公開中の記事を全件登録し直します。

データベースをほかのツールで直接書き換えたときや、検索結果が記事と合わないときは、次の順に試します。

1. sorus を終了して、もう一度起動します（サーバー版は再起動します）。起動したときに全件登録し直すので、ふつうはこれで揃います。
2. 直らないとき、または索引が壊れて起動できないときは、sorus を終了してから、サイトのフォルダの `search_index` を削除して起動します（1つ目のサイトはデータの場所（[インストールガイドの8章](install_guide.md#8-データの置き場所)）の `search_index`、2つ目以降は `sites/<id>/search_index`。サーバー版は環境変数 `SEARCH_INDEX_DIR` の場所）。消しても記事は失われません。

静的サイト公開の公開先の検索は、この索引を使いません。「サイトに反映」で作り直します。公開サーバーの索引の扱いもあわせて、[運用保守ガイドの「検索インデックスの更新と作り直し」](operations_guide.md#検索インデックスの更新と作り直し) を見てください。
